# Системные требования и рекомендации для {{ ydb-short-name }}

В этом разделе описаны основные требования и рекомендации по развёртыванию кластеров {{ ydb-short-name }}, которые применимы независимо от способа управления инфраструктурой — будь то [Ansible](../deployment-options/ansible/index.md), [Kubernetes](../deployment-options/kubernetes/index.md) или ручная настройка.

## Аппаратная конфигурация {#hardware}

Количество серверов и накопителей следует определять, исходя из требуемого уровня отказоустойчивости. Подробности приведены в разделе [{#T}](../../concepts/topology.md).

* **Процессор (CPU)**

  {{ ydb-short-name }} можно запускать только на процессорах с архитектурой x86-64, поддерживающих инструкции AVX2: Intel Haswell (4-е поколение) и новее, AMD EPYC и новее.

  Архитектура ARM официально поддерживается с версии 3.0.

* **Оперативная память**

  Рекомендуется использовать модули ECC для повышения надёжности и защиты от случайных аппаратных сбоев. Минимальный объём памяти — 2 ГБ на узел.

* **Дисковая подсистема**

  Поддерживаются HDD, SSD и NVMe-накопители, однако для высоких нагрузок настоятельно рекомендуется использовать NVMe.  
  {% include [_includes/storage-device-requirements.md](../../_includes/storage-device-requirements.md) %}

  {{ ydb-short-name }} не использует файловую систему для хранения данных, работая с блочными устройствами напрямую. Не следует монтировать раздел, используемый {{ ydb-short-name }}, или делить его с другими процессами, так как это может привести к деградации производительности.

  Производительность на виртуальных или сетевых хранилищах тестировалась и признана достаточной для продакшена.

  При планировании ёмкости учитывайте, что часть места используется системой: например, кластер из 8 узлов потребляет ~100 ГБ под статическую группу, а кластер с более чем 1500 узлами — около 200 ГБ. На каждом Pdisk также выделяются системные логи (~25.6 ГБ) и область размером не менее 0.2 ГБ.

## Программная конфигурация {#software}

Для запуска {{ ydb-short-name }} требуется Linux с ядром 4.10 и выше и libc версии 2.30 или новее. Примеры совместимых ОС: Ubuntu 20.04, Debian 11, Fedora 34 и более свежие.

{{ ydb-short-name }} использует TCMalloc в качестве аллокатора памяти. Для его оптимальной работы рекомендуется включить Transparent Huge Pages и Memory overcommitment.

Если сервер имеет более 32 физических ядер, рекомендуется запускать динноды в отдельных taskset/cpuset по 8–16 ядер. Например, на сервере со 128 ядрами можно запустить 8 диннод по 16 ядер.

ОС macOS и Windows не поддерживаются для серверного развёртывания, но могут использоваться для разработки и тестирования в [Docker-контейнере](../../quickstart.md).
